# KK GROUP Purchase — Supplier WhatsApp manual drafts (phase 2)

This stage adds procurement-specific **click-to-chat drafts**. It does **not**
send messages via Cloud API or depend on Meta credentials. The test sender in
`/settings/whatsapp` stays strictly segregated from supplier messaging.

## User flows

- **RFQ detail → Vendor responses → WhatsApp RFQ / Follow up**:
  available for assigned suppliers with pending responses, only to an operator
  with `rfq.send`, and not for cancelled/closed/completed RFQs.
  Drafts carry the RFQ number, project, response deadline, requested materials
  (maximum 8 displayed) and quotation requirements. They do not expose target
  rates and do not assert an approved purchase order.
- **PO detail → WhatsApp PO / Delivery reminder**: available to authorized
  procurement operators when the order is approved or in eligible post-approval
  delivery statuses. Drafts include PO number, project and delivery details.
  PDF attachments must be added manually.
- **Follow-up Center**: delivery rows offer an editable preview and manual
  WhatsApp deep link if an eligible vendor contact is stored.

The operator sees the vendor name and phone, reviews or edits the message and
must confirm both recipient and wording before clicking `Open WhatsApp draft`.
WhatsApp opens a prefilled conversation; the operator presses Send in WhatsApp.

## Security and accounting boundaries

- Clicking `Open` is **not** proof of sending or delivery. No RFQ/PO stage
  changes, no notification history entry, no implicit supplier consent and no
  success toast are generated by opening the URL.
- Supplier mobile numbers come only from RLS-scoped vendor master joins. If a
  valid WhatsApp destination cannot be parsed, the action is disabled until
  contact details are corrected in the vendor master.
- The existing role permission checks govern draft actions. Management Viewer
  can continue to view management summaries but not operating supplier actions.
- Do not send secrets, private bank details, internal target rates or approval
  links. The app cannot prove the WhatsApp account belongs to the supplier.
- The approved PO PDF is NOT automatically attached and the WhatsApp message
  is NOT a replacement for that signed document.
- No Supabase migration, server key, stored Meta access token, API charge,
  automated send, phone onboarding, account reassignment or Lovable credit.
- **Next step** (separate reviewed migration): RLS-protected consent registry,
  durable audited outbox, rate limits/idempotency, approved templates and
  opt-out checks before any actual automated supplier Cloud API sending.
